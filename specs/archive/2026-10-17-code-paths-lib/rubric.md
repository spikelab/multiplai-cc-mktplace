# Evaluation Rubric

Scope: the `code_facts` paths change, covering `paths.py`, `pyindex.py`, `entries.py`, `e2e.py`, the trace gate and prompts, `DirAnswers`, the `explore.ask` extensions, `schema/paths.v1.schema.json`, the tests and fixtures, and the `jsonschema` dependency.

Final score = Σ(score × weight) / Σ(weight).

## Code Architecture (weight: 2)

First, check whether the repo documents its own standards: CONTEXT.md, CONVENTIONS.md, an architecture or style guide, or ADRs. If it does, score against those, and suppress any baseline smell they endorse. If it does not, use the twelve-smell baseline. Report every smell as "possible <Smell>", never as a hard violation. Skip anything that ruff, the formatter or the type checker already enforces.

| Score | Criteria |
|-------|----------|
| 5 | Module boundaries match the plan, and each module has one axis of change:<br>• `paths.py` holds the contract: models, schema, `write_paths_file` and `map_paths` orchestration.<br>• `pyindex.py` holds the snapshot walk, parse cache, module resolution and import graph.<br>• `entries.py` holds discovery scanners, merge and diagnostics.<br>• `e2e.py` holds static test listing.<br>• The gate (`check_trace`) is a pure function with no model call.<br>• Discovery and listing are synchronous and take no `CallFn`.<br>• No module under `code_facts/` imports `walkthrough_pipeline`.<br>Shared logic exists once and is reused:<br>• `parse_command_line`, `resolve_command` and `command_edge` serve SKILL.md, hooks and e2e subprocess matching.<br>• `canonical_digest` serves trace and fallback keys.<br>• Path normalisation is shared by changed lines, places, `scope_paths`, gate rule 1 and fallback citations.<br>• `cli_targets` and `find_subcommand` are the single bridge between discovery and listing.<br>Domain concepts are typed: `EntryKind` StrEnum, `KIND_RANK`, Literal break, drop and stage reasons, `Location` and `HandlerRef` instead of tuples or dicts. Dispatch on entry kind is centralised, not repeated as if-chains across scanners, `cli_targets` and e2e matchers. `explore.ask` changes are additive and backward compatible. No speculative hooks or unused parameters beyond the specified signature. |
| 3 | Planned modules exist and the hard boundaries hold: no model call in discovery, gate or listing, and no `walkthrough_pipeline` import. Some possible smells remain, for example:<br>• possible Duplicated Code: path-normalisation or command-tokenising logic re-implemented in two scanners;<br>• possible Repeated Switches: `kind ==` chains in several places;<br>• possible Data Clumps: `(path, line_start, line_end)` or `(root, resolve, places, edges)` threaded through many signatures;<br>• possible Divergent Change: `entries.py` or `map_paths` growing into a single large function mixing scoping, tracing, ordering and cap.<br>Readability and maintainability suffer, but behaviour is not impaired. |
| 1 | Boundaries are violated in any of these ways:<br>• the gate or discovery calls the model;<br>• target code is imported or executed;<br>• `walkthrough_pipeline` is imported.<br>Or the code shows pervasive problems:<br>• heavy duplication across scanners;<br>• stringly-typed kinds and reasons that bypass the enums and Literals;<br>• `ask` changes that break existing callers;<br>• global mutable state, such as a module-level answer cache, that couples runs together. |

## Spec Compliance (weight: 3)

| Score | Criteria |
|-------|----------|
| 5 | Every WHEN/THEN scenario in all seven capabilities is implemented and covered by a test (entry-point-discovery, entry-point-model-fallback, path-tracing, trace-gate, path-scope-and-cap, paths-output-contract, e2e-test-listing).<br>**paths-output-contract**<br>• The schema has `$schema` set to draft 2020-12 and `$id` set to `paths.v1.schema.json`.<br>• The committed schema matches `schema_text()` byte for byte.<br>• All nine top-level fields are required.<br>• Cross-field invariants are enforced: `stops_at` paired with `break_reason`; `stops_at ≤ len(hops)`; a null `cap` and no `cap` or `no_changed_line` drops when unscoped; no overlap between `e2e` and `mocks_hop_2`; contiguous `p1..pN`.<br>• `write_paths_file` runs dump → jsonschema → `model_validate` → atomic `mkstemp` and `os.replace`, sets mode `0o666 & ~umask`, and leaves no `.tmp` file.<br>• `PathsSchemaError.pointer` is RFC 6901 and never raises `TypeError`.<br>**entry-point-discovery**<br>• All nine kinds are discovered with the exact naming, location, handler and edge rules (`__main__`, seeds, argparse, click/typer, `[project.scripts]`, SKILL.md, hooks).<br>• Merge by handler, `also_invoked_by` ordering, diagnostic reasons and their sort order, pruned directories, and multi-repo resolution all match the spec.<br>**trace-gate**<br>• Rules 1–8 run in order, with `hop_limit` keeping 20 and not triggering a re-ask.<br>• There is exactly one re-ask, and its answer replaces the first.<br>• An unrepaired break at hop 1 is dropped as `malformed_trace`, `empty_trace` or `cut_at_entry`.<br>• `recoverable` errors become a `trace_call_failed` drop. | 3 | Core flows work end to end: discovery of the main kinds, gated tracing with re-ask, scoping and cap, a schema-valid `paths.json`, and basic e2e listing. A minority of scenarios are missing or diverge, for example:<br>• a missing CommonMark fence nuance;<br>• Click 8.2 suffix stripping;<br>• Typer sub-app merging;<br>• tokenize fallback for f-strings;<br>• stale `{"error": …}` cache entries not purged;<br>• drop sort order slightly off;<br>• `PathsSchemaError.pointer` not escaping `~` and `/`.<br>No divergence breaks determinism or the no-execution guarantee. |

## Integration Coherence (weight: 2)

| Score | Criteria |
|-------|----------|
| 5 | Each block's produced interfaces match what later blocks consume, with exact signatures.<br>**Discovery feeds tracing:** `Entry.known_edges` and merged invoker edges reach both the trace prompt and gate rule 7(b). `places` reach the prompt and rule 7(c).<br>**Gate output feeds publication:**<br>• `GateOutcome` maps cleanly onto `TracedPath`.<br>• Internal `BreakReason` values that are never published (`malformed_answer`, `empty_trace`, `entry_mismatch`) only ever become drops.<br>• Coverage counts only retained hops.<br>**Ordering and lookups:**<br>• Ids are assigned after ordering and cap.<br>• `list_e2e_tests` is keyed by those final ids.<br>• It consumes `cli_targets`, `parse_command_line` and `PyIndex` resolution consistently with discovery.<br>**One cache-key scheme:**<br>• `canonical_digest` plus `TRACE_PROMPT_VERSION` keys both trace and fallback answers.<br>• Lookups work identically for in-memory dicts and `DirAnswers`.<br>• Output is rebuilt from this run's keys, never by iterating the cache directory.<br>**Shared model calling:** fallback survivors flow through the same reachability, trace-limit, tracing, coverage and cap pipeline. Every model call goes through the caller's `CallFn` via the extended `ask`, with `allowed_tools=["Read","Grep","Glob"]` and `cwd` layered over `call_kwargs`.<br>**Library surface:**<br>• `code_facts/__init__.py` exports the new names and keeps all old ones unchanged.<br>• `jsonschema>=4` is declared in `pyproject.toml` and the lock is updated.<br>• Python models, the committed JSON schema and the written files round-trip losslessly, with the `from` alias handled and `by_alias=True`. |
| 3 | The pipeline works end to end, but some seams are loose, for example:<br>• edges are carried in the prompt but recomputed differently in the gate;<br>• fallback entries skip one scope stage;<br>• e2e matchers re-derive CLI tokens instead of using `cli_targets`;<br>• cache keys built ad hoc in one call site;<br>• a minor export or lockfile omission.<br>Within-block tests pass, but these gaps cause no observable cross-block failures. |
| 1 | Block contracts are inconsistent in any of these ways:<br>• signatures differ from the stated interfaces;<br>• ids are assigned before the cap, or e2e listings attach to the wrong path;<br>• gate and prompt disagree on edges or places;<br>• cache keys collide across commits or depend on order;<br>• `ask` changes break existing explore callers;<br>• model and schema drift so that `write_paths_file` rejects valid results or accepts invalid ones;<br>• the dependency is undeclared, or prior exports were removed. |
