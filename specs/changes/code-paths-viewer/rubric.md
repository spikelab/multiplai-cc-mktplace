# Evaluation Rubric

## Code Architecture (weight: 2)
| Score | Criteria |
|-------|----------|
| 5 | Loader is split cleanly: `inspect_paths` returns a `PathsStatus` NamedTuple, `paths_beside` is a thin wrapper that logs once and never raises, and `walkthrough status` reuses `inspect_paths` instead of duplicating the checks. The only import is `from code_facts.paths import PathsResult`. Nothing under `lib/code_facts`, `REVIEW_FILES`, `review_pipeline/target.py`, the Slack share/export code, the `walkthrough.v1` schema or `walkthrough put` changes. All derivation logic lives as pure functions in `logic.js` and is listed in `api`: `resolveTab`, `isRefuted`, `countedFindings`, `findingsByPath`, `sortPaths`, `hasCountedE2e`, `pathCardModel`, `pathsSummary`, `hasUnlistedTests`, `resolvePathRefs` and `findingPathsSection`. `app.js` only renders models, using `el(...)`/`textContent` under `// --- paths ---`. The inline tab reset at `app.js:423` is moved into `resolveTab`. `allowed_paths`/`file_view` extend through the `extra`/`extra_ranges` defaults, with no forked code paths. `_path_files` and `_path_ranges` sit in `server.py` next to the `PathsResult` they read. Any baseline smells (e.g. possible Feature Envy, possible Duplicated Code between card and finding-section label logic) are minor and framed as judgment calls. |
| 3 | Structure mostly follows the plan, with some leakage. Examples: part of the ordering or count logic is computed inline in `app.js` rather than in `logic.js`; status-line formatting re-runs part of the validation; ranges or files are collected ad hoc in the route rather than through helpers. Some possible smells: Duplicated Code between `pathsSummary` and the card ordering's `byPath` computation, Primitive Obsession with raw status strings scattered around, or Repeated Switches on status. Forbidden areas are untouched. |
| 1 | Validation logic is duplicated across the server and the `walkthrough status` CLI, or `REVIEW_FILES`/`lib/code_facts`/share-export code is modified. `serialise_paths` is called, or a paths schema is defined locally. Rendering logic is embedded in `app.js` with no pure helpers, or uses `innerHTML`. `allowed_paths`/`file_view` signatures break existing callers. |

## Test Quality (weight: 1)
| Score | Criteria |
|-------|----------|
| 5 | Every row of the `inspect_paths`/`paths_beside` table is a distinct test. Each asserts both the payload `paths` value and the exact count of `caplog.records`, and the absent case also asserts that no record mentions `paths.json`. The stale cases cover each failure: 7-char prefix, reverse prefix, `base_sha`, case-only difference and empty/missing `head_sha`. The `OSError` case uses a monkeypatched `read_text`, and `REL_PATH` rejection uses `../../etc/passwd`. The payload-equality test compares the full payload (findings, checks, walkthrough) for rejected vs. absent files. The no-model test monkeypatches `run_agent` to raise and asserts on observable outcomes: populated `paths`, and a walkthrough exactly equal to the stored one in order. It does not rely only on a call flag. The drift guard walks nested `model_fields`. `allowed_paths` tests cover tree-review scoping, a stale file staying blocked, `listed = []`, a null handler, and >4000-line unfolding. Node tests use the shared fixture to assert exact orderings (p1,p4,p2,p3,p5,p6; inline B,D,A,C; document order for empty `byPath`), exact summary strings, `structuredClone` immutability checks, a literal `<script>` name, and the `innerHTML` source guard. `resolvePathRefs`/`findingPathsSection` cover dedupe, unknown ids, null inputs and refuted F-C. Server tests never build `findings.json` with empty or duplicate ids. `SKILL.md` text guards, the four status lines, and the unchanged walkthrough contract are tested. No sleeps, and no mock-only assertions. |
| 3 | Most table cases and helper tests are present, with gaps. Examples: some cases assert status but not the log count; the drift guard checks only top-level fields; the immutability checks are missing; the summary tests cover the fixture but not the inline singular, four-path or empty cases; the `SKILL.md` heading-adjacency check is missing. Mocks are used reasonably, though some assertions are weak (e.g. `is not None` instead of an equality check). |
| 1 | Tests are sparse or superficial. Examples: one happy-path loader test; no stale or prefix cases; assertions limited to `run_agent.called`; no Node tests for ordering, summary or path refs; the fixture is not validated against `PathsResult`; tests rewritten to match buggy behaviour; a production hook added only for testing. |

## Spec Compliance (weight: 3)
| Score | Criteria |
|-------|----------|
| 5 | Every WHEN/THEN scenario across the four specs is implemented and verified. **viewer-paths-loading:** `paths.json` is read only from `<review_dir>/paths.json`. The file is accepted only on exact, full, case-sensitive `commit == head_sha`. The ordered checks produce `absent`/`invalid`/`stale`/`accepted` with the specified detail strings. There is exactly one warning for `stale` and `invalid`, none for `absent`, and the loader never raises. The payload is `model_dump(mode="json")`, or `null`, and zero paths serve `{"paths": []…}`. File order is preserved. No model is called. Hop, entry and non-null handler files become viewable only for accepted files, including tree reviews and `listed = []`. **viewer-paths-panel:** The tab sits immediately after Checked with `data-tab="paths"` and count `paths.length`, and is hidden like Checked when there is no accepted file. Cards are ordered with counted-finding paths first, then document order. Each card shows entry name, kind and invokers. Hops link at `line_start` and highlight `line_start..line_end`. A broken trace shows `trace broken`, the `break_reason` and the `hops[stops_at-1]` file:line, and truncates hops. Counted findings exclude refuted and hidden findings, and the heading is omitted when there are none. Mocked tests are marked `not counted`, and `no e2e test` appears when appropriate. Excluded fields are absent. The summary line has correct pluralisation and counts mocked-only paths in `k`. The muted unlisted-tests note uses the exact text. Zero paths show only `No entry points reach the changed code.`. Share/export output is unchanged. **finding-path-links:** The Paths section appears on every finding, refuted ones included, in finding order, deduped. Known ids link through `showPathCard` (switch tab, scroll, `is-target` on one card only, cleared on target switch). Unknown ids appear in place marked `not in paths.json`. The section is omitted when ids are empty or missing or no file was accepted. **walkthrough-path-guidance:** `SKILL.md` has a gated subsection directly after the `facts.json` section with the three instructions and the schema note. The four `paths:` status lines are correct. There is no `path_ids` field, and the walkthrough contract is unchanged. The fixtures match the specified p1–p6 and F-A..F-D shapes. The version bump and CHANGELOG are present. |
| 3 | Core flows work: loading, tab, cards and finding links. Some scenarios are missing or partially wrong. Examples: the count is shown while hidden; the summary pluralisation or the mocked-only `k` count is off; broken-trace location uses the wrong hop; `is-target` is not cleared on target switch; the unlisted note or zero-paths message is missing; the `SKILL.md` placement or schema note is incomplete; the fixture lacks one required case. |
| 1 | Major requirements are missing or violated. Examples: prefix or case-insensitive `commit` matching; a stale or invalid file still served or making files viewable; the loader raises or crashes the review; refuted or hidden findings counted on cards; finding links absent; the walkthrough is regenerated or a model is called; the `walkthrough.v1` contract is changed; `paths.json` is looked for in other locations. |

## Integration Coherence (weight: 2)
| Score | Criteria |
|-------|----------|
| 5 | The server, payload, front end, CLI and docs agree on one contract. The same `inspect_paths` decision drives the `/api/targets/<slug>` `paths` key, the `allowed_paths` extension, `_path_ranges` and the `walkthrough status` line. As a result, a file that the viewer rejects never makes files viewable, never shows a tab or Paths section, and never triggers walkthrough path guidance. The front end gates every paths feature on the single `target.paths != null` check. Field names consumed in JS (`entry.location.path/line`, `handler`, `hops[].line_start/line_end`, `stops_at`, `break_reason`, `tests.e2e[].node_id`, `tests.mocks_hop_2`, `test_listing_skips`) match the `PathsResult` dump, and the drift guard locks that in. Hop links open file views that the server actually permits, with the correct ranges unfolded. `findingsByPath` is computed once, from `countedFindings(shownFindings(...))`, and that one value feeds both card ordering and the summary. Finding links resolve to `path-card-<id>` DOM ids produced by `pathCardModel`. The `code-facts` dependency, `[tool.uv.sources]` editable path, regenerated `uv.lock`, version bump and CHANGELOG are consistent, so `check_changelog.py` passes. |
| 3 | The layers mostly line up, with some seams. Examples: the CLI status re-implements part of the acceptance check; the summary and ordering compute `byPath` separately; hop links work but highlight the wrong range in large files; a JS field name relies on an undocumented shape; `uv.lock` or the changelog is out of sync. |
| 1 | The layers disagree. Examples: the server accepts a file the CLI reports as stale, or the reverse; hop links point at files the server refuses; JS reads field names not present in `model_dump(mode="json")`; finding links target DOM ids that cards don't render; paths UI appears when the payload `paths` is `null`; the dependency is missing so imports fail outside the dev environment. |
